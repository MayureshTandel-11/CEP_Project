# Plan-adherence model: target, data and evaluation design

Status: **design + synthetic pipeline only. No real-user outcome data exists yet, and nothing
here has been validated on real users.**

## Why the current classifier cannot go beyond the rules
The legacy classifier (`ai-ml/app/training/dataset.py`) is trained on rows that are themselves
generated by the same kind of hand-written thresholds that label them (`label_row()` plus 7% noise).
A model fit to that can at best re-learn the rules: on a seed-777 hold-out the Random Forest scored
*below* the rules (0.918 vs 0.939 accuracy). Its "accuracy" measures agreement with the rules, not
usefulness to a user. A model can only add information if its label is an *observed outcome* the
rules do not define.

## Target: `adhered_7d` (binary)
For a weekly activity-plan snapshot taken at day **T** (end of day T) with planned daily exercise
`planned_daily_minutes` (P):

- Outcome window: days **T+1 .. T+7**.
- `observed` = at least **4 of 7** days have a logged `exercise_minutes` value.
- If observed: `adhered_7d = 1` iff mean(logged exercise_minutes over the window) >= 0.8 * P, else 0.
- If not observed: the row is **excluded** from training/evaluation (never counted as 0). The
  excluded fraction is reported, because informative missingness can bias the observed set.

## Features (only information available at time T)
Static: `bmi`, `age`, `activity_score`, `goal_code`, `planned_daily_minutes`.
Trailing window days **T-6 .. T** (inclusive of day T): `win_log_days`, `win_sleep_mean`,
`win_water_ratio_mean`, `win_steps_ratio_mean`, `win_exercise_mean`, `win_exercise_ratio`
(vs. P), `win_stress_mean`, and `prev_adhered` (previous snapshot's label, only if that
snapshot's window had ended by T and was observed).
Missing values stay `NaN` (RandomForest in scikit-learn >= 1.4 handles them); no imputation.
Dropped: `gender_code` (no causal reason, fairness risk) and the legacy ML category (circular).

## Schema (long format)
- `users`: `user_id, age, gender, bmi, activity_level, goal, data_origin`
- `daily_logs`: `user_id, day, sleep_hours, water_ml, steps, exercise_minutes, stress_level, data_origin`
  (any value may be missing; the whole row may be absent)
- `snapshots`: `user_id, T, planned_daily_minutes, data_origin`
- derived `examples`: features + `adhered_7d`, `observed`, `user_id`, `T`, `data_origin`

`data_origin` is `synthetic` or `real`. Training/evaluation CLIs refuse synthetic data unless
`--allow-synthetic` is given and stamp every report with `data_origin` and a disclaimer.

## Leakage and contamination controls
1. **Temporal:** features use days <= T only. Enforced by a perturbation test: rewriting all logs after
   T must not change any feature.
2. **Duplicate-user:** splits are by user (70/15/15); no user appears in two splits (asserted).
3. **Temporal split + purge:** train snapshots have T <= t_a; validation T >= t_a + 8; test T >= t_b + 8
   (gap > the 7-day outcome window), so no train outcome window overlaps later evaluation time.
4. **Canaries:** a deliberately leaky feature (future mean) must be detected by the audit; a model
   trained on shuffled labels must score near chance on the test split.
5. Test split is touched once, after model/threshold choices are frozen on validation.

## Baselines and metrics
Baselines: (a) majority class; (b) *persistence* (`prev_adhered`, else majority);
(c) *rule*: adhered iff `win_exercise_mean >= 0.8 * P`. Metrics: macro-F1, per-class recall,
balanced accuracy, PR-AUC, ROC-AUC, Brier, calibration bins. User-clustered bootstrap (resample users)
gives CIs, including for the paired macro-F1 difference vs. the best baseline.

## Pre-registered acceptance (fixed before any run)
Replace/augment the legacy classifier only if, on real held-out users: macro-F1 exceeds the best baseline
by >= 0.03, the paired 95% CI excludes 0, and minority-class recall does not fall below the best baseline's.
**Results on synthetic data can only show the pipeline works; they cannot satisfy this on their own.**

## Synthetic generator assumptions (see `ai-ml/app/adherence/simulate.py`)
Seeded. Hidden per-user latent traits (motivation, consistency) drive daily exercise through an AR(1)
process; planned minutes depend on activity level and goal (as in the app's rules); logging probability
is higher for motivated users (informative missingness). Labels are computed from simulated daily logs
with the same function used for real data. These assumptions are invented by the authors, not measured.

## Real-data requirements before training
Persist at plan time: `featureSnapshot`, `plannedDailyMinutes`, `modelVersion`, `adjustmentApplied`;
a randomly assigned control holdout (no ML adjustment) to estimate causal effect; a research-consent
flag; minimum volume (suggest >= 500 users and >= 2,000 observed snapshots, both classes >= 200) before
reporting any metric. Without a control holdout the model predicts adherence but we cannot claim it
improves outcomes.

## Reproducing the synthetic pipeline run

```
cd ai-ml
PYTHONPATH=. python -m app.adherence.train --allow-synthetic --users 4000 --seed 7 --out report.json
```

One run (seed 7, 4,000 simulated users, 49% of snapshots observed) gave, on the held-out test users
(908 snapshots, 393 users): macro-F1 persistence 0.726, rule 0.723, model 0.753; paired gain vs.
persistence +0.027 (95% user-clustered CI roughly 0.001 to 0.054), below the pre-registered 0.03
bar; the model's recall on the minority class (not adhered) 0.694 vs. persistence 0.740. Shuffled-label
canary: ROC-AUC 0.503. **These numbers describe the simulator, not people**, and the verdict is
`NOT_APPLICABLE_SYNTHETIC`. Thresholds were not tuned after seeing this result. Regenerate; do not
copy numbers from this paragraph into reports.
